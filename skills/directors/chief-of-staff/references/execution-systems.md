# Execution Systems — Projects, Reviews & Bottlenecks

## Project Management Standard

Every project that gets resources must have all seven fields defined before work begins.
A project without an owner is not a project — it is a wish.

```
PROJECT NAME:         [Specific, not vague]
OWNER:                [Single person — not "team"]
OBJECTIVE:            [One sentence — what done looks like]
PRIORITY LEVEL:       [1–5 per prioritization framework]
BRAND / DEPARTMENT:   [Which entity this lives under]
TIMELINE:             [Start date → Target completion]
MILESTONES:           [3–5 checkpoints with dates]
RESOURCES REQUIRED:   [Capital / Time / People / Tools]
BLOCKERS (CURRENT):   [What is in the way right now]
SUCCESS METRIC:       [How we know it worked]
COMPLETION CRITERIA:  [Specific — not "when it feels done"]
NEXT ACTION:          [The single next physical step + who does it + by when]
```

**Hard rule:** If the Next Action field is blank — the project is stalled, not in progress.

## Weekly Operating Rhythm

Run this cycle every week without exception. Consistency is the system.

### Monday — Priority Selection (30 minutes)

```
WEEKLY REVIEW QUESTIONS:
1. What did we complete last week?
2. What didn't move and why?
3. What is the single most important thing to complete this week?
4. What three projects need the most attention?
5. What can be dropped, delegated, or deferred?

WEEKLY PRIORITIES (MAX 3):
  Priority 1: [Project + specific outcome by Friday]
  Priority 2: [Project + specific outcome by Friday]
  Priority 3: [Project + specific outcome by Friday]

BLOCKERS TO RESOLVE THIS WEEK:
  [List what is blocking top priorities — and who resolves each]
```

### Wednesday — Mid-Week Check (15 minutes)

```
PROGRESS CHECK:
  Priority 1: [On track / Blocked / Complete]
  Priority 2: [On track / Blocked / Complete]
  Priority 3: [On track / Blocked / Complete]

ADJUSTMENTS NEEDED:
  [Any resource reallocation or priority shifts required]
```

### Friday — Execution Review (20 minutes)

```
COMPLETED THIS WEEK:
  [List with outcomes]

NOT COMPLETED — WHY:
  [Honest assessment — capacity / priority shift / blocker / poor scoping]

CARRY FORWARD:
  [What moves to next week + adjusted next action]

WINS TO NOTE:
  [Progress worth acknowledging — not just completions]

NEXT WEEK SETUP:
  [Top priority for Monday — decided Friday, not Monday morning]
```

## Execution Review Protocol

For any project that has been "in progress" for more than two weeks without a milestone hit,
run this diagnostic:

```
EXECUTION DIAGNOSTIC:
  What exactly are we building?           [If this is unclear — stop and clarify first]
  Why does it matter to the business?     [If no clear answer — kill or deprioritize]
  Who owns it?                            [One person. If multiple — reassign.]
  What is blocking progress?              [Specific — not "busy"]
  What is the next physical action?       [If "figure out X" — that IS the action]
  What outcome are we pursuing?           [Measurable. Not vague.]
  What is the deadline?                   [If none — set one now or cut it]
```

If a project cannot answer all seven questions clearly — it is not ready to consume resources.
Pause it. Clarify it. Then restart.

## Bottleneck Identification System

Run a bottleneck scan weekly. The goal is to catch friction before it becomes failure.

### Categories to scan:

**Delays** — Projects or tasks that have missed their stated timeline
- Flag any deliverable overdue by more than 3 days without communication
- Determine: capacity issue / dependency issue / scope creep / unclear ownership

**Dependencies** — Tasks waiting on other tasks or people
- Map any project where progress requires input from another brand, person, or system
- If the dependency has no ETA — escalate and set one

**Capacity Constraints** — Not enough time, capital, or skill available
- Which priorities are under-resourced?
- What gets dropped if resources don't increase?

**Process Failures** — Workflows breaking repeatedly
- Any task that has to be redone or corrected more than twice needs a process fix, not more effort

**Communication Gaps** — Information not reaching the right people
- Are all stakeholders on a project aware of current status?
- Is anyone making decisions based on stale information?

**Execution Risks** — Projects with high likelihood of missing target
- Flag any project with an unclear next action, no owner, or an optimistic timeline
- Surface these before they become problems, not after

### Bottleneck Report Format

```
BOTTLENECK SCAN — [Date]

CRITICAL (Blocking revenue or high-priority initiative):
  [Item] — [Root cause] — [Resolution owner] — [Resolution deadline]

MODERATE (Creating drag but not blocking):
  [Item] — [Root cause] — [Resolution owner] — [Resolution deadline]

MONITORING (Early signal, not yet critical):
  [Item] — [What to watch] — [Trigger for escalation]

RESOLVED THIS WEEK:
  [Items cleared + what fixed them]
```

## Meeting Framework

No meeting exists solely for discussion. Every meeting produces at least one of:

- A decision made
- An action item assigned with owner and deadline
- A blocker removed
- A priority confirmed or changed

**Meeting template:**

```
MEETING: [Name]
DATE: [Date]
ATTENDEES: [List]
OBJECTIVE: [One sentence — what this meeting must produce]

AGENDA:
  [Item 1] — [Time] — [Owner]
  [Item 2] — [Time] — [Owner]

DECISIONS MADE:
  [Decision] — [By whom] — [Effective when]

ACTION ITEMS:
  [Task] — [Owner] — [Deadline]

NEXT MEETING: [Date + purpose if recurring]
```

If a meeting ends without completing this template — the meeting was not complete.
